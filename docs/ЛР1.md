# Лабораторная работа 4. Отчёт

## Часть В. Рефакторинг god-класса

### Таблица нарушений SOLID (до рефакторинга)

| Принцип | Строка / фрагмент | Почему нарушение |
|---------|-------------------|------------------|
| SRP | `File.ReadAllLines(inputFile)` | Класс читает файл — это ответственность ввода/вывода. |
| SRP | `var parts = line.Split(' ', 3)` | Класс разбирает строку — это отдельная ответственность парсинга. |
| SRP | `if (level == "DEBUG") continue` | Класс фильтрует записи — ответственность фильтрации. |
| SRP | `var formatted = $"{date} \| {level} \| {message}"` | Класс форматирует вывод — ответственность форматирования. |
| SRP | `Console.WriteLine(...)` + `File.AppendAllText(...)` | Класс пишет в несколько приёмников — ответственность записи. |
| OCP | `foreach ... if (level == "DEBUG")` | Фильтр жёстко зашит: добавление нового правила фильтрации потребует правки метода. |
| OCP | `Console.WriteLine` + `File.AppendAllText` | Приёмники жёстко зашиты: добавление Telegram/БД потребует правки метода. |
| DIP | `Console.WriteLine`, `File.AppendAllText`, `File.ReadAllLines`, `new FileInfo` | Класс напрямую зависит от конкретных I/O-классов (`File`, `Console`), нельзя подменить в тестах. |
| LSP | — | Нарушений нет: наследования нет. |
| ISP | — | Нарушений нет: интерфейсов нет. |
